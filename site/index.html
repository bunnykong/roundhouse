  • LobstersThe proving lane A real, community-run app. Most of it transpiles; what doesn’t yet shows up as diagnostics you can read.
  • CampfireThe live axis Basecamp’s chat app. It runs: two tabs, one room, one live message over Action Cable.
  • MastodonThe moonshot One of the largest Rails apps. Types in about two seconds in a browser tab; it doesn’t run yet.

Why bother

Success shouldn’t mean a rewrite.

Rails gets a small team to a working product fast, and CRuby on Puma serves it well for years. Then success brings constraints nobody planned for: a cloud bill that grows with every worker, users far from your region, places CRuby can’t run at all. The usual answer is a rewrite, and it’s an expensive one.

Roundhouse keeps Rails as the source of truth and turns the runtime into a choice you make at build time. You keep the conventions too, and they count for more now that agents write much of the code: resources :posts stands in for the routes of seven actions and their URL helpers, which no one, person or model, has to write or read. Rails to build with, and native speed to run on if Spinel gets all the way there.

Types without annotations

Rails was already typed.

has_many :comments is a type declaration nobody wrote down. Roundhouse reads the whole app and works out the rest: which class an association returns, what a column deserializes to, whether a find_by can come back nil.

No boot, no database, no annotations. The same analysis runs in your terminal, your editor, your agent and a browser IDE that never uploads your code.

Native Ruby, through Spinel

Stay in Ruby.
Ship one binary.

Spinel is Matz’s ahead-of-time Ruby compiler. It reads a whole program, turns it into C and builds one executable, with no interpreter.

Roundhouse’s Ruby output is Ruby that Spinel can compile, because the metaprogramming is already gone; the result is one binary with, by default, a SQLite file beside it. Of the compiled targets it behaves most like Rails, since it runs Roundhouse’s framework runtime itself rather than a translation of it. Campfire runs this way today, and OCRAN does the whole compile in one command: ocran --roundhouse path/to/app.

How we know it works

Rails is the oracle.

We send the same request to Rails and to the generated app, and the responses have to match, DOM node for DOM node, JSON value for value.

01

Emitted tests

Every target ships with its own test suite, and it has to pass.

02

A live comparison

Requests go to Rails and to the generated app, and the responses are compared after normalization.

03

The browser, too

Turbo updates and Action Cable get end-to-end browser tests, because a static diff can’t see them.

Faster, even in Ruby.

Lowering Rails to plain Ruby pays off on CRuby too. On the reference blog, with the same interpreter, YJIT and Puma, the generated Ruby serves 2.7× to 5.4× the requests per second of stock Rails, depending on the endpoint. On the JVM the gap on /articles is 11.2×.

Get started

Check your app.

Install the snapshot binary and run roundhouse check on any Rails checkout. Nothing boots and nothing is uploaded. Snapshots cover macOS on Apple silicon and Linux x86-64, with untested macOS Intel and Windows builds alongside; anywhere else, build from source with Cargo.

Install guideRead the docs

Terminalsh
