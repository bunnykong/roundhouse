# Open problems

A loop that stops changing is only the first requirement. We also need the same equations and answer under different schedules, types that admit runtime values, and affordable re-checking after edits. The [facts](facts.md) and [attempts](attempts.md) distinguish pinned measurements, executable models and proofs. Older measurements must be refreshed before describing current main.

1. **Discover the same equations.** Dispatch targets, return and parameter slots, closure slots and their writers are discovered during inference. Different schedules can therefore solve different systems (F5, F16). Can the complete logical structure be declared from the program, or discovered monotonically without retracting edges or changing reference routing? The check is matching final structure digests across shuffled schedules, complete read/write membership, matching carried-state answers and zero extra-round movement. Predeclaration additionally requires matching start/end structure.

2. **Make every writer obey its algebra.** The merged parameter and ivar join repairs are useful foundations, but return replacement, narrowing and history-sensitive size cuts remain separate obligations. For every carried slot, writer permutations and regroupings must produce the same result; joins must satisfy commutativity, associativity, idempotence and pending identity. Transfers must preserve information as their inputs grow, and widening must preserve possible values. F14 shows why better precision counts alone cannot validate a merge rule.

3. **Distinguish pending, unresolved and gradual values.** Pending inference contributes no evidence; unresolved dispatch records a modeling gap; gradual values retain dynamic possibilities. These meanings must survive producers, sharing, joins, dispatch and export. Pending is not language-level non-return: treating it as `Bottom` fails the F19 runtime witnesses. F18's keep-unresolved control avoids false nil-only receivers but loses precision and hides errors. Progress requires producer-specific semantics, the paired error census, fixed coverage denominators and the oracle together.

4. **Check soundness beyond settling.** Every recorded value must belong to its inferred type, with missing selections rejected and unresolved coverage reported. The lab now publishes the settling witness, pending comparisons and destructuring matrix. F17–F20 show that settling, fewer errors and fewer oracle rejections can each conceal defects. Traces from the public apps' own test suites are still needed, with stable mappings from runtime observations to static slots. Passing sampled traces establishes witnessed soundness on that coverage, not all-execution soundness.

5. **Make exact incremental replay fast.** Warm and cold must agree after changed returns, removed reads and deleted support around cycles, including dependencies and controller contexts. In F15's historical six-edit condition, warm wall time excluding validation was 21.55–32.01 times whole cold-check wall time, with one timed pair per edit. Profile loading, guards, replay and fresh typing separately. A useful first gate is matching every shadow while warm costs no more than cold per edit; the [frontier's](frontiers/incremental.md) target remains exact re-checking in milliseconds. Report those timing scopes separately.

Start with structure and unknown semantics, then integrate writer repairs. Runtime trace preparation and replay profiling can proceed alongside them. Keep the cold shadow until replay's premises are established. The [lab](https://github.com/bunnykong/roundhouse-fixpoint-lab) provides the witnesses and proofs; [#617](https://github.com/rubys/roundhouse/issues/617) records the staged proposal and its corrections.
